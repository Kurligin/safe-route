# Витрина: где решение работает, где его граница и какие риски

Сценарии лежат в [`../../scenarios/showcase/`](../../scenarios/showcase/): группы `works/` (работает) и
`limits/` (граница). Все файлы проверены схемой симулятора.

В этой папке — прогоны финального контроллера (`ours`) и базового контроллера организаторов
(`baseline`, без истинной позы), seed 1–3. Файлы называются `<сценарий>__<кто>__s<seed>`:
- `.json` — отчёт;
- `.txt` — вывод `amrsim run`;
- `.jsonl` — лог, для seed 1; для `l2` лог есть ещё и для seed 2.

Отдельно лежит [`lost/`](#потеря-ориентации-т4-о2) — демонстрация потери ориентации.

Моменты `t` взяты из логов seed 1, если не сказано иное. Их можно открыть в АРМ.

**Касание стены почти по касательной** в допустимом сценарии не воспроизводится:
- эталонный путь идёт не ближе 1,39 м центром от стен карты;
- объезд — не ближе R + 0,3;
- правило отступа замедляет до 0,3 м/с, если корпус проходит ближе 0,3 м к стене или предмету.

На тест-водителе красной команды (`research`, отчёт 10 §2; сценарий недопустимый) упор боком под
3° лидаром не различим: ошибка позы до 1,5 м в режиме по умолчанию.

## Потеря ориентации (Т4, О2)

**В допустимых сценариях `lost` не наступает.** Проверены:
- 44 сценария красной команды: seed 1, 0 тиков `lost`;
- `l6_blind_run` выше;
- все наборы стенда: открытые, 30 скрытоподобных на seed 1–6, 21 стресс.

Почему фильтр не теряется:
1. Скан сопоставляется с картой в каждом тике. Точки незнакомых предметов отсекаются гейтом, а при
   расхождении карты — строже, до 0,2 м.
2. Масштаб колёс калибруется по собственным командам.
3. Одна «ошибка» не превращается в `lost`. `lost` объявляется, только если скан долго не совпадает с
   картой (12 тиков из 15) **и** второй источник тоже сомневается: σ > 0,5 м, ГНСС стойко расходится
   или скан отвергается 20 тиков подряд (`localization.py:Localizer._lost_monitor`).

**Демонстрация с внесённой ошибкой** — [`lost/`](lost/). Контроллер тот же. Обёртка
`lost/inject_controller.py.txt` (текст обёртки, чтобы проверка не разбирала его как код) один раз, в t = 30,0, сдвигает его оценку позы на (+5, +2) м, как будто
фильтр принял ложный фикс. Сценарий `01_clear`, seed 1. Дальше по логу
`lost/inject_01_clear__s1.jsonl`:

| t, с | Что происходит |
|---|---|
| 30,0 | ошибка позы 5,4 м |
| 31,1 | `mismatch:map`: скан не ложится на карту |
| 32,9 | фильтр объявляет `lost`: ГНСС стойко расходится. Команда v = 0, торможение со статусом `moving`, пока скорость > 0,05 (правило статуса) |
| 34,0–36,1 | стоит, статус `lost`, note `lost`, v = 0 |
| 36,2 | перепривязка к ГНСС и подтверждение сканом, ошибка 0,07 м, движение продолжается |

Итог прогона — 100, эпизодов нет.

**Юнит-тест** `tests/test_lost.py`: синтетическая комната со столбами, похищение на 12 м стоя.
- Фильтр объявляет `lost` не позже чем через 5 с.
- Восстанавливается за ≤ 6 с, ошибка < 0,2 м.
- Контроллер всё это время отвечает v = 0, w = 0, status `lost`, note `lost`.

## Риски

- **Поддон, упавший ближе 1 м к оси перед платформой.** Итог 0 (`l1`), удара нет. Оракул тоже 0,
  поэтому в скрытых по правилам допуска таких сценариев нет. Похожий, но допустимый случай — поддон
  падает сбоку, пока платформа проезжает (`w4`, t ≈ 63): минимальный зазор в движении 0,11 м, удара
  нет.
- **Пешеход, слипшийся с поддоном**, считается предметом. `l2` seed 2 стоит −13,2, но без fatal.
  Это принятый компромисс: вариант «неизвестное неподвижное = человек» обходится в −2,55 на
  скрытоподобных.
- **Разворот попутного пешехода** — около −1 за эпизод (`l3`, gen_012 на всех seed).
- **Двое невнимательных под навесом на плече C → B** — таймаут плеча, около 72 за сценарий (`l4`).
  В стресс-наборе так ведут себя 2 сценария swarm из 21.
- **Длинный незнакомый забор вплотную к стене в тумане** — ложные «люди», таймаут на 2 seed из 3
  (`l5`). Сценарий проходимый: оракул (`baseline --cheat`, seed 1) набирает на нём 100. Значит, это
  слабость нашего восприятия: обрывки забора, мерцающие в тумане, принимаются за людей. Забор 70 м
  длиннее, чем в генераторе организаторов (6–20 м).
- **Скачок оценки позы, если он всё же случится.** Поведение показано прогоном с внесённой ошибкой
  (`lost/`, см. выше): `mismatch:map`, `lost`, остановка, перепривязка, итог 100. Опасный случай —
  скачок незадолго до дока: платформа может встать не в той точке (`off_target`), и следующая
  миссия не начнётся. Другие моменты и величины сдвига проверялись только внутренне, в комплект
  эти прогоны не входят. В сценариях комплекта скачков у фильтра не было ни разу.
- **Упор боком под ≤ 3°** лидаром не различим (см. выше). Закрыт отступом 0,3 м, в допустимых
  сценариях не встречался.

## Как воспроизвести

Из папки симулятора, `<repo>` — путь к репозиторию:

```bash
python -m amrsim run <repo>/scenarios/showcase/works/w6_estop_pallet.json --controller <repo>/controller.py --seed 1 --log out/w6.jsonl
python -m amrsim run <repo>/scenarios/showcase/works/w6_estop_pallet.json --controller baseline/controller.py --seed 1
# потеря ориентации: копия репозитория, в которой controller.py переименован в team_controller.py,
# а рядом лежит lost/inject_controller.py.txt под именем controller.py
python -m amrsim run scenarios/01_clear.json --controller <копия>/controller.py --seed 1 --log out/lost.jsonl
```
