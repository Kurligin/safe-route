# Безопасный маршрут — контроллер беспилотной платформы

Контроллер для симулятора amr-sim, кейс «Безопасный маршрут». Он доставляет грузы между складом,
магазинами и зарядкой без ГНСС в тени, в тумане и снеге и рядом с людьми. Подход кратко описан в
[APPROACH.md](APPROACH.md).

## Как запустить

Нужен архив симулятора организаторов `amrsim-participants`. Удобнее всего распаковать его рядом с
репозиторием:

```
<папка>/
├── amrsim-participants/   # архив организаторов
└── safe-route/            # этот репозиторий
```

Ниже `<repo>` — путь к этому репозиторию, `<sim>` — путь к `amrsim-participants`.

### А. Контроллер в симуляторе

Нужны Python 3.10+ и numpy. Других зависимостей у контроллера нет.

```bash
cd <sim>
python3 -m venv .venv && . .venv/bin/activate
python -m pip install -r <repo>/requirements.txt

# статическая проверка правил
python -m amrsim check <repo>

# один сценарий
python -m amrsim run scenarios/02_gnss_shadow.json --controller <repo>/controller.py --seed 1 \
    --report out/02.json --log out/02.jsonl

# batch: репозиторий лежит в папке команд teams/<имя>/
mkdir -p teams && cp -r <repo> teams/safe-route
python -m amrsim batch teams scenarios --seeds 1,2,3 --jobs 4 --out out/batch.csv
```

`check` даёт `result: OK` без нарушений. Предупреждения (WARNING) относятся только к `arm/` и
`web/`: серверы рабочего места запускают симулятор и поэтому импортируют `subprocess`,
`http.server`, `threading`, `fastapi`. Контроллер эти модули не импортирует, у каждого такого
предупреждения стоит пометка «not imported by controller.py» или «blocked at run time».

### Б. Лёгкое рабочее место оператора (`arm/`)

Сервер — только стандартная библиотека Python; numpy нужен интерпретатору, который запускает
прогоны (подойдёт venv из варианта А). Из корня репозитория:

```bash
cd <repo>
python arm/server.py --sim <sim> --python <sim>/.venv/bin/python
# открыть http://127.0.0.1:8765, остановить — Ctrl+C
```

Без `--sim` (или с `--readonly`) работает только просмотр готовых прогонов из `results/`.

### В. Полный веб-сервис в Docker (`web/`)

Нужен Docker с Compose v2 (Docker Desktop или docker-ce). Образ собирается из `web/`, в него
копируются контроллер, `scenarios/` и `results/` этого репозитория и симулятор из `<sim>`.

```bash
cd <repo>/web
AMRSIM_DIR=<sim> docker compose up --build -d   # <sim> — абсолютный путь;
                                                # если архив лежит рядом с репозиторием, AMRSIM_DIR не нужен
# открыть http://127.0.0.1:8098
docker compose logs -f     # журнал
docker compose down        # остановить (прогоны и свои сценарии сохраняются в томах docker)
docker compose down -v     # остановить и удалить тома
```

Первая сборка занимает несколько минут: скачиваются образы node и python. Папку `<sim>` Docker
передаёт в сборку целиком, поэтому большую `out/` после batch лучше удалить или указать в
`AMRSIM_DIR` чистую распаковку архива. В сервисе:

- просмотр и сравнение прогонов;
- запуск пачек `amrsim run` из вкладки «Запуск» (по 2 одновременно);
- конструктор сценариев с проверкой схемой симулятора;
- CSV.

Подробности — [web/README.md](web/README.md).

Готовые прогоны открытых сценариев лежат в [results/](results/README.md): среднее 99,91 на seed 1–3.
Дополнительные возможности с указанием сценария, момента и места в коде описаны в
[results/features.md](results/features.md). Свои сценарии — в [scenarios/](scenarios/README.md).
Где решение работает, где его граница и какие риски, показано в
[results/showcase/](results/showcase/README.md). Там же — потеря ориентации и восстановление.

## Структура

| Модуль | Что делает |
|---|---|
| `controller.py` | класс `Controller`: конвейер на тик, проверка входа и выхода, страховка шага |
| `localization.py` | `Localizer`: EKF позы с масштабом одометрии, уходом ИНС и смещением ГНСС; сканматчинг, границы тени, детектор упора, режимы «расхождение карты» и «потеряна» |
| `perception.py` | кластеры и треки неизвестных лидарных возвратов, люди с центром и скоростью, статика |
| `mission.py` | фазы миссии, флаг забора, arrived |
| `planner.py` | путь, маршрут к точке забора (A*), профиль скорости, объезд смещением (`Bypass`), трек впереди |
| `follow.py` | regulated pure pursuit, разворот на месте, задний ход и повторный заход в доке |
| `safety.py` | последний слой: люди (прогноз, уступание), коридор, «слишком близко», estop, отступ 0,3 м |
| `geometry.py` | углы, полигоны, растр знакового расстояния до стен, ray cast |
| `motion.py` | закон скорости платформы из config |
| `config_team.py` | все пороги и переключатели (`LOC_MODE = "odom"` или `"model"`) |

Коды в поле `note` ответа предназначены для рабочего места оператора:
- `wait:person`, `slow:person` — стоп или замедление из-за человека;
- `wait:object`, `slow:object` — стоп перед предметом или замедление ради отступа 0,3 м;
- `bypass:object`, `estop:object` — объезд, аварийное торможение;
- `pickup`, `dock`, `zone:<v>` — фазы движения и ограничение зоны скорости;
- `mismatch:map`, `lost`, `err` — скан расходится с картой, локализация потеряна, исключение в шаге.

## Тесты

Симулятор для тестов не нужен:

```bash
python -m unittest discover tests
```

Тесты рабочего места: `python -m unittest discover -s arm/tests` (стандартная библиотека) и
`cd web/backend && pip install -e ".[dev]" && pytest` (FastAPI).

В наборе контроллера 82 теста:
- фильтр позы на синтетической карте;
- правила людей и estop;
- объезд, закон скорости и док;
- машина состояний миссии;
- формат ответа и битые входы;
- потеря ориентации и восстановление.

## Рабочее место оператора (АРМ)

Два варианта с одним интерфейсом: лёгкий [arm/](arm/README.md) (запуск — вариант Б) и полный
веб-сервис [web/](web/README.md) (вариант В, он же развёрнут как демо).

Что умеют:
- карта площадки, положение платформы и оценка позы, пешеходы во времени;
- журнал рейсов, остановки с причинами и эпизоды штрафов (клик переводит плеер к моменту);
- проигрывание с паузой и перемоткой, сравнение двух прогонов;
- запуск `amrsim run` из интерфейса с результатом в списке;
- конструктор сценариев, экспорт CSV.
