# Рабочее место оператора (АРМ)

Локальное веб-приложение: проигрывание прогонов на карте площадки, сравнение двух прогонов,
запуск новых прогонов симулятором и конструктор сценариев. Работает в браузере без интернета
и сторонних сервисов. Сервер написан на стандартной библиотеке Python, интерфейс — HTML, CSS
и JavaScript без сборки.

## Запуск

Из корня репозитория, одной командой:

```bash
python arm/server.py --sim /путь/к/amrsim-participants
```

и открыть в браузере <http://127.0.0.1:8765>.

| Флаг | Что задаёт | По умолчанию |
| --- | --- | --- |
| `--sim` | папка симулятора организаторов (в ней `scenarios/` и `baseline/`) | `$AMRSIM_DIR`, затем `../amrsim-participants` рядом с репозиторием |
| `--python` | интерпретатор с numpy, которым запускаются прогоны | тот, которым запущен сервер |
| `--port` | порт | 8765 |
| `--host` | адрес | 127.0.0.1 |
| `--parallel` | сколько прогонов идут одновременно, 1–4 | 2 |
| `--runs` | ещё папка с прогонами (`.jsonl` + `.json`), флаг можно повторять | — |
| `--readonly` | только просмотр: запуск прогонов и сохранение сценариев выключены | выключен |
| `--allow-host` | имя сервера, под которым АРМ открывают через reverse-proxy (нужно для запуска и сохранения), флаг можно повторять | — |

Пример с виртуальным окружением симулятора:

```bash
python arm/server.py --sim ../amrsim-participants --python ../amrsim-participants/.venv/bin/python
```

Без симулятора (или без numpy у `--python`) сервер тоже стартует: просмотр прогонов работает,
а кнопки запуска и «Сохранить в «Свои»» выключены, причина написана рядом с ними и в консоли.

## Зависимости

Сам сервер — только стандартная библиотека Python 3.10+. Для запуска прогонов нужен
интерпретатор, в котором есть numpy (его требует симулятор): `pip install -r arm/requirements.txt`.
Корневой `requirements.txt` относится к контроллеру и не меняется.

## Что умеет

**Прогоны.** Список всех прогонов: `results/` (логи и отчёты, в том числе раскладка
`logs/` + `reports/`), `arm/runs/` (запущенные из АРМ) и папки из `--runs`. Для выбранного прогона:

- карта площадки со сворачиваемой легендой в левом нижнем углу: проезды, здания, зоны (тень ГНСС, скоростные, запретные, зона людей), доки,
  расхождения карты с миром (контейнер не на карте, снесённое здание), упавший поддон;
- положение платформы (истина) и оценка позы контроллера, след обеих траекторий, маршрут рейса;
- пешеходы в каждый момент времени, красным — ближе 3 м к платформе;
- панель «Сейчас»: статус, причина из note контроллера по-русски, рейс, скорость, ошибка позы,
  зазор до человека;
- журнал рейсов (время против дедлайна, итог) и журнал остановок, замедлений и штрафных эпизодов
  из отчёта; клик по строке переводит плеер в этот момент;
- счёт сценария по блокам;
- плеер: пуск и пауза (пробел), скорость ×1…×32, перемотка кликом или протяжкой по шкале,
  стрелки ±1 с, с Shift ±10 с, режим «следовать за тележкой»; шкала времени с полосами условий
  (тень ГНСС, туман, пропадание спутника, поддон), рейсов и остановок, графики скорости с пределом
  зоны, ошибки позы и зазора до человека;
- экспорт CSV рейсов и CSV остановок и штрафов (UTF-8 с BOM, разделитель «;», десятичная запятая —
  открываются в Excel);
- «Прогнать заново с seed» — настоящий запуск того же сценария и контроллера с другим seed,
  результат сразу открывается.

**Сравнение.** Два прогона одного сценария рядом: две карты, общая шкала времени, счёт по блокам
и разница, журналы обоих. По умолчанию в пару берётся другой контроллер на том же seed. Если пары
нет, её можно запустить прямо из панели сравнения.

**Запуск.** Сценарии (открытые, учебные, скрытоподобные, стресс, проверочные, свои) × контроллеры
(наш и Baseline) × список seed. Каждый прогон — команда симулятора

```
python -m amrsim run <сценарий>.json --controller <контроллер>/controller.py --seed <seed> \
    --report arm/runs/<id>.json --log arm/runs/<id>.jsonl
```

Очередь показывает ход каждого прогона и итог; готовые прогоны сразу появляются во вкладке
«Прогоны» и в истории. Имя прогона: `<контроллер>__<сценарий>__s<seed>`.

**Конструктор.** Карта площадки, маршрут из реальных сценариев (склад → цех A → склад,
склад → цех B и другие), снег, туман и пропадание спутника по времени, пешеходы (внимательные
и невнимательные), поддон, контейнер, которого нет на карте, снос здания. Сценарии организаторов
и наши наборы открываются только для просмотра, с них можно сделать копию. Карта, id расхождений
карты, `provide_detections` и `generator` берутся из самого сценария (у скрытоподобных своя тень ГНСС);
вторые полосы тумана и окна без спутника сохраняются. «Сохранить в «Свои»»
проверяет пределы (до 512 КБ, `duration_s` ≤ 900, пешеходов ≤ 30, событий ≤ 20, расхождений карты
≤ 10, точек ≤ 5000) и схему самого симулятора и кладёт сценарий в `arm/custom/`. id выдаёт сервер
(`custom_NN`); перезаписать свой сценарий можно только с токеном правки, который браузер получил
при первом сохранении, иначе сохраняется новый. «Запустить» сохраняет
и запускает наш контроллер и Baseline на seed 1; «Скачать сценарий» отдаёт JSON схемы amr-1.0
(в режиме просмотра — исходный файл без изменений).

## Устройство

| Файл | Что делает |
| --- | --- |
| `server.py` | HTTP-сервер, очередь прогонов, сохранение своих сценариев |
| `armcore.py` | разбор лога JSONL и отчёта JSON в формат интерфейса, поиск прогонов и сценариев |
| `static/` | интерфейс: `index.html`, `app.js`, `style.css` |
| `tests/` | тесты (27): `python -m unittest discover -s arm/tests` |
| `runs/`, `custom/` | создаются при работе: прогоны из АРМ и свои сценарии (в git не попадают) |

**Защита.** POST принимаются только с `Content-Type: application/json` (браузер тогда сначала шлёт
preflight, на который сервер не отвечает), с `Host` из списка (localhost, адрес `--host`,
`--allow-host`) и `Origin` той же страницы. За один запрос — не больше 40 прогонов, в очереди — не
больше 120; запрос с ошибкой в любом seed не ставит ни одного прогона. Прогоны идут пулом из
`--parallel` воркеров. Для публичного показа без запуска — `--readonly`.

API сервера: `GET /data.js` (сводки прогонов, сценарии, карта), `GET /api/run/<id>` (прогон
целиком, `?lite=1` — сводка), `GET /api/scenario/<id>`, `GET /api/jobs`, `POST /api/launch`
(`{"scenario", "controllers": [...], "seeds": [...]}`), `POST /api/scenario` (`{"id"?, "token"?, "scenario"}` → `{"id", "token"}`). Сценарии витрины
(`scenarios/showcase/**`) видны отдельной группой «Витрина».
